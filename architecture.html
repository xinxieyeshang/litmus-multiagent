01 / Orchestration Topo

星型编排拓扑

四个专业智能体彼此不直接通信，只与协调智能体（Orchestrator）交互。协调者负责分解任务、收集状态、触发融合——专业智能体只专注自己的指标，职责单一、可独立替换模型。

任务下发 TASK_ASSIGNED 状态回流 TASK_COMPLETED 融合请求 FUSION_REQUEST
设计要点：协调智能体在代码里被明确约束「不执行任何科学计算；指标公式、标准化、权重、数据划分、H1 标签不可变」——把「编排」和「计算」彻底解耦，这是多智能体系统可维护、可审计的关键。
02 / Communication Protocol

消息协议与状态机

自研 14 种消息类型的通信协议，统一消息格式（message_id / task_id / from / to / type / payload / timestamp），Agent 有 5 态状态机（IDLE / RUNNING / COMPLETED / FAILED / RETRYING）。

communication/agent-protocol.ts协议定义
// 星型拓扑：专业 agent 只与 orchestrator 通信
export type MessageType =
  | 'TASK_ASSIGNED'   // 协调者 → 专业agent：分配任务
  | 'TASK_PROGRESS'   // agent → 协调者：进度
  | 'RETRY_DECIDED'  // agent 自主：重试异常子任务
  | 'FALLBACK_USED'  // agent 自主：切换备用工具
  | 'INFO_REQUEST'   // agent 请求补充信息
  | 'FUSION_REQUEST' // 协调者 → 融合agent
  | 'FUSION_COMPLETED' // 融合完成
  // …共 14 种

export interface AgentMessage<T> {
  message_id: string; task_id: string;
  from: AgentName; to: AgentName | 'broadcast';
  message_type: MessageType;
  status: MessageStatus;
  payload: T; timestamp: number;
}

协议特性

  • 不是直接函数调用，而是带 ID、时间戳、状态的可追溯消息流
  • 每次任务执行都有完整日志，可回放每个智能体的每一步
  • 进度消息节流：每 5% 上报一次，避免万篇级任务的消息洪泛
  • 信息请求带 5 秒超时（Promise + 订阅 + 清理），防悬挂等待

// 进度消息节流：每5%或总数变化时上报，避免消息洪泛

03 / Research Integrity by Design

实验诚信：用类型系统硬隔离数据泄漏

科研诚信被写进代码约束：融合智能体从类型层面接触不到 H1 标签，从结构上杜绝「看着答案打分」的可能。

Agent 的权限边界

可自主重试 · 备用工具 · 异常处理 · 请求补充信息 · 标记失败

禁止改指标公式 · 改标准化方式 · 改融合权重 · 改数据划分 · 碰 H1 标签

类型层隔离：FusionInput 接口里根本没有 isH1 / h1Classification / h1Rating 字段，编译期就无法传入。
communication/agent-protocol.ts设计约束
// 设计约束（实验诚信红线，代码层硬隔离）：
// - 任何 Agent 的消息 payload 中禁止携带 H1 标签

04 / Fusion Algorithm

融合算法与异常检测

融合智能体验证四路信号后再加权：min-max 归一化 → 退化信号（无区分度）权重置零并重分配 → 加权求和。全程记录PMID缺失、分值越界等异常。

agents/fusion-agent.ts退化检测 + 融合
function isDegenerate(scores: number[]): boolean {
  const min = Math.min(...scores);
  const max = Math.max(...scores);
  return max - min < 1e-10;  // 无区分度
}
// 退化信号权重置零，剩余重新归一化
let w1 = degenerate.s1 ? 0 : w.signal1;
let w2 = degenerate.s2 ? 0 : w.signal2;
const wSum = w1 + w2 + w3 + w4;
const fusedScore = wSum === 0 ? 0.5
  : (sc.s1*w1 + sc.s2*w2 + sc.s3*w3 + sc.s4*w4) / wSum;

融合前的四道校验

  • PMID 一致性：缺失 / 任务外 PMID 全部记录
  • 分值范围：非 [0,1] 有限数值视为异常
  • 退化信号检测：无区分度信号自动降权
  • 全退化兜底：返回 0.5，不产生 NaN
为什么要这样：LLM 输出不稳定是常态，融合层必须对脏数据鲁棒，同时在异常发生时如实上报（而不是悄悄吞掉）——这是系统可信的基础。
05 / Agent Autonomy

单智能体的自主决策：以 S1 为例

智能体不是被动执行——它在限定权限内自主决策：前置质检省 LLM 调用、8 路并发、JSON 结构校验、失败自动重试一轮、兜底分，最后产出质检报告。

前置质检

摘要缺失或少于 50 字符的论文直接标记失败，不浪费一次 LLM 调用。

分批并发

每批默认 50 篇，批内 8 路并发调用豆包模型（doubao-seed-2-0-lite），实时回报进度。

结构校验

校验 score ∈ [0,1] 且五维创新类型字段齐全，结构不通过进入重试队列。

自主重试

失败论文追加一轮重试；仍失败则保留工具兜底分（0.3）并如实上报，不伪造成功。

质检报告

汇总三项检查：JSON 结构、摘要完整性、LLM 调用成功率（含重试挽回篇数）。
